# Rubika SAF Queue 1.2.0 RC2 — سورس قابل ساخت، نه APK تأییدشده

این بسته ادامهٔ پروژهٔ **Rubika SAF** است و صرفاً سورس کد تولیدشده برای ساخت مستقل Android و سرویس Go را در بر دارد. هیچ APK قدیمی در بسته قرار نگرفته و هیچ APK تازه‌ای در محیط جاری ساخته نشده است.

## وضعیت فعلی (۱۱ نوامبر ۲۰۲۶)

- سورس مستقل Android با شناسهٔ `com.rubiqueq.saf.queue`، نسخهٔ `1.2.0-rc2`، برای جلوگیری از تداخل امضای آزمایشی با نسخهٔ قبلی.
- ورود به حساب روبیکا با شماره + OTP و رمز دومرحله‌ای اختیاری در سرویس Go از طریق سورس اینترنتی MIT Rubingo (ورود واقعی آزموده نشده).
- خواندن CSV/XLSX، تبدیل شماره‌های فارسی و عربی به قالب یکسان، حذف تکراری‌ها و شرط رضایت ثبت‌شده (`opt_in=true` و `opt_in_source`).
- زمان شروع آینده، فاصلهٔ ۳۰ تا ۸۶۴۰۰ ثانیه، START / PAUSE / ادامه، ذخیرهٔ صف در سرور، وضعیت‌های pending/submitted/skipped/uncertain.
- اصلاح RC2: صف دارای ارسال ثبت‌شده یا نامطمئن دیگر بدون اتمام یا بررسی قابل جایگزینی نیست؛ محدودیت زمانی کوتاه پیش از ارسال صرفاً ارسال بعدی را به عقب می‌اندازد و صف را نیازمند START مجدد نمی‌کند.
- اصلاح RC2: آپلود رسانه روی دیسک با فایل موقت و rename اتمیک انجام می‌شود؛ قبل از ارسال تصویر، صحت هش SHA256 با شناسهٔ تصویر بررسی می‌شود.
- ساخت backend در Dockerfile حالا سورس پین‌شدهٔ Rubingo را دانلود می‌کند (به GitHub و go proxy نیاز دارد).
- Workflow جدید: ساخت از سورس، `go test -race ./...`، بررسی APK با `apksigner` و `aapt2` و آپلود فایل به‌عنوان **خروجی توسعه‌ای**؛ نه انتشار نهایی.

## ساخت محلی / GitHub

پیش‌نیاز: JDK 17، Android SDK 35، Gradle 8.9، Go 1.26، اینترنت برای Gradle / GitHub / Go modules.

```bash
bash scripts/fetch_rubingo_source.sh
cd server && go mod tidy && go test -race ./... && go build .
cd .. && gradle :app:assembleDebug
```

برای ارسال سورس RC2 به مخزن شخصی/سازمانی که دسترسی `git push` دارید، روی دستگاه دارای `git` و `gh` احرازهویت‌شده:

```bash
bash scripts/publish-to-github.sh Rubiqueq/fantastic-broccoli
```

این اسکریپت پوشهٔ کد برنامه و سرور را به مخزن متصل می‌کند و دو workflow قدیمیِ تولید نسخه‌های قبلی را حذف می‌کند. اجرای GitHub Actions بعد از push شروع می‌شود. **کلید API، کد ورود، نشست و فایل مخاطبان را به GitHub آپلود نکنید.**

## راه‌اندازی سرویس صف (Railway)

- Dockerfile جدید باید از آخرین سورس روی GitHub ساخته شود.
- Mount یک volume دائمی روی `/data` و تنظیم `QUEUE_DATA_DIR=/data` برای دوام صف الزامی است.
- `API_KEY` یک مقدار محرمانهٔ طولانی است؛ در برنامهٔ عمومی یا فایل سورس قرار ندهید. اگر مقداری قبلاً در چت منتشر شده، پیش از بهره‌برداری تولیدی کلید را تعویض کنید.
- برای ورود موفق حساب شخصی و ارسال به مخاطب، سرویس روبیکا، دسترسی شماره‌به-GUID و وضعیت حساب باید به‌صورت واقعی بررسی شوند.

## قالب فایل مخاطبان

`phone,opt_in,opt_in_source,message`

نمونهٔ رضایت‌دار فقط برای آزمون: `0912XXXXXXX,true,فرم رضایت مستقیم,سلام`. فایل‌های نمونهٔ ۹۹۹تایی قبلی هرکدام **صفر ردیف با رضایت ثبت‌شده** دارند؛ برنامه از آن‌ها پیام ارسال نمی‌کند.

## معیارهای تحویل نهایی

موفقیت GitHub Actions به‌تنهایی عملکرد پیام‌رسان را ثابت نمی‌کند. قبل از تحویل نهایی باید: ساخت و امضا با SDK، دریافت OTP از حساب واقعی، ورود موفق، تبدیل شماره به GUID صحیح، ارسال متن و تصویر به مخاطب مجاز، دریافت تأیید گیرنده، توقف/ادامه و بازیابی بعد از راه‌اندازی مجدد، و امنیت سرور بررسی شود. شواهد آزمون واقعی فعلاً در دسترس نیستند. **این بسته RC2 یک APK نهایی نیست.**
